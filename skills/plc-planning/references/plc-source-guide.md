# PLC Source Guide

Prefer repo-local templates when present. Use these external references when a
new SRD/SADD structure needs grounding:

- NASA SWEHB SRS guidance: requirements should cover system overview,
  functional requirements, interfaces, data, quality characteristics,
  constraints, qualification provisions, traceability, phased delivery, testing,
  and rationale.
- NASA SwDD guidance: design docs should capture decisions, alternatives,
  assumptions, limitations, constraints, design drivers, and selection criteria.
- arc42: architecture docs should cover goals, constraints, context, building
  blocks, runtime view, deployment, crosscutting concepts, architecture
  decisions, quality requirements, risks, and glossary.
- Quality attribute scenarios: write measurable quality requirements rather than
  unverifiable adjectives.

For technology-specific PLCs, cite official docs for the external system or
format being integrated.
